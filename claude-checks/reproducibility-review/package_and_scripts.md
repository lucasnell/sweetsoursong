# Reproducibility review: package, scripts, tests

Reviewed 2026-10-30 at `main` (551363a). Scope: could an outside reader clone the repo, regenerate the computed panels of Figs 2-6 and SI Table S2, and verify the package?

## Verdict

Mostly yes for the computed content, with one trap and several undocumented gaps. I ran all five scripts on a `git archive` copy of HEAD (scratchpad, not the working tree). Each ran without error, in about 3 s (Fig 2), 3 s (Figs 3-4), 25 s (Fig 5), 39 s on 8 cores (Fig 6), and 3 min 18 s (Table S2). The CSVs for Fig 2, Figs 3-4, Fig 5, and Table S2 are byte-identical to the ones already in `_data/`, and the Fig 6 outcome counts match `_data/04-fig6.log`. The package side is clean. The weaknesses are: the archived release (`v2.0.0`, which the manuscript's concept DOI resolves to) has a README and a script name that disagree with the manuscript; the README test instruction needs a package that no install route provides; the figures the scripts make are not the figures in the manuscript, and the README does not say so; and the Mathematica fixtures cannot be regenerated by an outsider without a hard-coded path and a Wolfram licence, which is not stated.

## Findings

### Major

**M1. The tagged release differs from `main` in exactly the places an outside reader will look first.** (verified by `git show v2.0.0:...`)
- At `v2.0.0` the script is `_scripts/05-si-table-s1.R`, headed "SI Table S1", and the tag's README lists "SI Table S1" (README line 47 and 69 at the tag). The manuscript now calls it Table S2 (`tab:numerics`, and CLAUDE.md). `main` renames it (commit 5a93fc6), but the Zenodo concept DOI always resolves to the latest published release, which is `v2.0.0`, not `main`. A reader who follows the DOI finds no Table S2 script.
- The `main` README's PPM route installs `lucasnell/sweetsoursong@v2.0.0` (README line 98-99), so the code a reader gets from that route also has the old name. The tag's README also has a different install snippet (an `install_version` loop), so the instructions on GitHub `main` and in the archive differ.
- 12 commits separate `v2.0.0` from `HEAD`; only the README and the script rename touch reproducibility files (`git diff --stat v2.0.0 HEAD -- R DESCRIPTION _scripts tests NAMESPACE renv.lock README.md`).
- Fix: cut `v2.0.1` (or re-point before anyone cites a version DOI) so the archive contains the renamed script and current README, and change the README's install ref to the new tag. CLAUDE.md records a decision not to write a release-specific DOI into the repo; that is compatible, since the tag name is not a DOI.

**M2. The README tells readers to run `devtools::test()`, but no install route installs devtools.** (verified: `grep` of `renv.lock` finds jsonlite, renv, and testthat, not devtools; DESCRIPTION Suggests has no devtools; README line 56, "The tests run with `devtools::test()`")
- After `renv::restore()`, `devtools::test()` fails with "there is no package called devtools". The PPM route has the same gap.
- Fix: say `testthat::test_local()` (testthat is installed by both routes), or `R CMD check`. Add the command and the expected result (the PROJECT_INDEX says 346 tests pass; README gives only "about 2 minutes").

**M3. The README does not say the figures produced by the scripts are not the manuscript's figures, and the stochastic panels cannot match them.** (inferred from CLAUDE.md "Manuscript figure panels are the Mathematica exports (decided 2026-10-05)", `_scripts/02-fig3-4.R:34,80`; not in README)
- README line 55-56 says the scripts "make the computed panels of Figs 2-6". A reader will compare a ggplot PDF to the published panel. Fig 3A-B (Gillespie paths, `set.seed(15)`, `gillespie_reduced`) and Fig 4 (50 plants drawn with `set.seed(777)`) are random draws; the published ones come from Mathematica's RNG, so they cannot agree beyond statistics. The deterministic and threshold panels should agree, but no script or test compares R output against the published panel images or the numbers behind them in a way a reader can run. The closest, `claude-checks/r-port/verify_manuscript_numbers.R`, lives in a folder the README describes only as "numerical checks".
- Fix: add a short README paragraph: which panels are deterministic (2B-E, 3C/4 right column, 5B-F, 6, Table S2) and match the published ones numerically, which are random (3A-B, 4 left columns) and match in distribution only, which panels are schematics or Illustrator work (see M4), and where the numerical comparison lives.

**M4. Schematic and composite parts of the figures are not produced by anything in the repo, and only 2A and 5A are named.** (inferred)
- README line 57-58 names 2A and 5A as schematics. Fig 1 (model diagram, parameters D, transitions E), the Illustrator layout (`~/Box/_sweetandsour/_figures/*.ai`), and any annotations added to Figs 3, 4, and 6 live in Box, outside the repo. The scripts also use their own titles and size (for example "P_R = 1.0: coexistence" in `02-fig3-4.R:93`). An outsider cannot tell what was added by hand.
- Fix: one sentence in the README saying that Fig 1, the schematic panels, and the final layout are made in Illustrator and not reproduced, and that Fig 1D parameters equal `ss_params()` (plus the test that checks this, if one exists; I did not find one).

**M5. Fixture regeneration needs Mathematica, a hard-coded absolute path, and an unnamed command; the README does not say any of this.** (verified by reading `claude-checks/r-port/r_port_reference.wl:14`)
- README line 34-36 says the fixtures were "generated by `claude-checks/r-port/r_port_reference.wl`". The script sets `root = "/Users/lucasnell/GitHub/Stanford/sweetsoursong"` and calls `definitions_unified.wl` from `claude-checks/chris-files/`. The usage line is in the script header only (`wolframscript -file r_port_reference.wl chop|nochop`); CLAUDE.md adds that `wolframscript` needs a `WolframKernel` environment variable and one kernel at a time, and that is not in the repo-facing docs. The notebook-derived settings are tracked in `notebook_inputs.txt`, which is good, but `extract_notebook_inputs.wl` needs the git-ignored 12 MB notebook.
- Fix: replace the hard-coded path with a path derived from the script location (`NotebookDirectory[]` or `$ScriptCommandLine[[0]]`), add a "Regenerating the fixtures" paragraph (needs Wolfram 15.0.1 with EcoEvo 1.7.2 as the CLAUDE.md states; fixtures are committed, so this is optional for verification), and state that Wolfram is not needed to run the tests.

### Minor

**m1. A fresh clone with renv fails confusingly if the reader runs a script before restoring.** (verified: running `Rscript _scripts/01-fig2.R` in a clean copy bootstrapped renv from the network, then printed "One or more packages recorded in the lockfile are not installed" and "there is no package called 'sweetsoursong'")
The README order (install, then scripts) is correct, but `renv.lock` does not contain `sweetsoursong` itself (verified: no such entry), so `renv::restore()` alone never makes `library(sweetsoursong)` work. The README has the extra `install.packages(".", repos = NULL, type = "source")` line (line 79), which covers this, so the README is accurate; it is just easy to skip. A one-line note in `00-preamble.R` (a `requireNamespace` check with an instruction) would help. Also, `.Rprofile` (`source("renv/activate.R")`) downloads renv from the internet on the first R start, which is normal renv behaviour but means the no-renv route is the only one that works fully offline.

**m2. The scripts silently reuse stale caches.** (verified by reading `_scripts/00-preamble.R:32-38`; `02-fig3-4.R`, `03-fig5.R`, `04-fig6.R`, `05-si-table-s2.R` all use `cached()`)
`cached()` returns an existing `_data/*.rds` without checking that it matches the current package version or inputs. In a fresh clone `_data/` is empty (only `.gitignore` is tracked), so the first run is correct. A reader who edits a parameter, or who upgrades the package, and re-runs gets the old result with no message. Fix: store `packageVersion("sweetsoursong")`, `options("sweetsoursong.chop")`, and `pars` with the cached object and recompute on mismatch, or print "using cached ..." and tell the reader to delete `_data/*.rds`. The README does not mention the cache at all.

**m3. Local `_data/` and `_figures/` hold old v1.0.0-era files that the new scripts do not make.** (verified by `ls -la _data _figures`)
`_data/` holds a 2.2 GB `big-stoch-mutual-inv-growth-sims.rds` (Dec 2024), `big-stoch-*.rds`, and `*.mx` files; `_figures/` holds `invasion-*.pdf`, `u-stochastic-main.pdf`, `determ-u*-d_yp*.pdf`. They are git-ignored so an outsider never sees them, but on the author's machine a figure name could be mistaken for current output. Also `_data/05-si.log` is a leftover from the earlier script name. Fix: move them to an archive folder outside the project, or into `_figures/zzz-unused`.

**m4. `outcome_grid()` uses `parallel::mclapply`, and Fig 6 uses `detectCores() - 2`.** (verified by reading `R/outcomes.R:31`, `_scripts/00-preamble.R:18`)
On Windows `mclapply` with `mc.cores > 1` stops with an error. On a 2-core machine `n_cores` is 1 and Fig 6 runs serially: my 8-core run took 39 s of wall time and 3 min 41 s of CPU, so a serial run would take about 4 min. Not a problem on Unix. Fix: note "Windows: set `cores = 1`" in the `outcome_grid` docs, or fall back to `1L` when `.Platform$OS.type == "windows"`. The runtimes are not in the README; add them (about 5 min total on 8 cores, of which Table S2 is 3.3 min).

**m5. The PPM route is untested by me and claims more than it can guarantee.** (inferred; not run because I did not install anything)
README line 84-95: "the snapshot has every package in `renv.lock` at the recorded version" and "Tested on macOS on 2026-10-05". On Linux, binaries come from PPM only for supported distributions, and source builds need system libraries for ggplot2's dependencies (textshaping, ragg, systemfonts need freetype, harfbuzz, fribidi, png, jpeg headers). The README names no system dependency, and the package itself needs none (Matrix, deSolve, parallel are in R). Fix: add "Linux: ggplot2 may need these system libraries" or limit the claim to the platform tested, and state which OS and R 4.6.1 build was used (it does: aarch64-apple-darwin23).

**m6. `DESCRIPTION` says `R (>= 4.4)` but `renv.lock` and README pin R 4.6.1.** (verified: `renv.lock` line 3, DESCRIPTION line 21) 
Not wrong, since the lock and the minimum answer different questions, but the README should say that other R versions are untested for numerics (`renv::restore()` will warn on a mismatch), because the tests compare to 1e-13 to 1e-14 against Mathematica (`test-vacancy.R:9-12`, `test-rates.R:8`), which may depend on BLAS and LAPACK. I did not test another R or BLAS.

**m7. Exported API is documented, but three numerics-affecting choices are in different places.** (verified)
All 38 exports have an `.Rd` page. `sweetsoursong.chop` is documented in `man/chop.Rd` (source `R/chop.R:3-11`) and README line 32; `inv_b(method=)` in `R/metacommunity.R:39-47` and README. Neither is mentioned in `?inv_y` or `?meta_equilibrium`, and there is no package-level help page (`?sweetsoursong`) and no vignette or worked example. A user of `inv_threshold("b", ..., method = "chris")` reads the argument from the `.Rd` only. `00-preamble.R` sets `options(sweetsoursong.chop = FALSE)` explicitly, which is good. Fix: add a `sweetsoursong-package.R` page listing the options and defaults; add `CITATION` (no `inst/CITATION` exists) pointing to the concept DOI and the manuscript, so `citation("sweetsoursong")` works.

### Nit

- **n1.** `tests/testthat/helper-fixtures.R:12-13` skips a test when no fixture exists, so a reader whose clone lacks the JSON files (for example a shallow copy that dropped `tests/`) sees "skipped", not "fail". The fixtures are tracked and I found no problem, but `test_local()` output should be checked for skips; say so in the README.
- **n2.** Most tests are tagged `skip_on_cran()` (`test-full.R:2,19,52`, `test-gillespie.R:2,29`, `test-invasion.R:34`, `test-examples.R:35`). With `NOT_CRAN` unset (as under `R CMD check` in some setups), the Mathematica comparisons for the full model, the Gillespie checks, and the invasion thresholds do not run. Say in the README to run with `NOT_CRAN=true` (devtools and `test_local` set it automatically; plain `Rscript -e 'testthat::test_dir(...)'` or `R CMD check` may not).
- **n3.** Gillespie tests (`test-gillespie.R`) check statistical agreement (5 standard errors, batch means), not exact paths. That is the right design for a random process, and it uses fixed seeds, but the seeds depend on R's default `sample.kind`; fine for R >= 3.6.
- **n4.** Scripts read and write relative paths (`"_figures"`, `"_data"`), so they must be started from the project root; stated in `00-preamble.R:1-2` and README line 49-50 ("from the project root"). `Rscript` from another directory fails with an unhelpful message. Fix: `stopifnot(file.exists("DESCRIPTION"))` in the preamble.
- **n5.** The README's directory listing omits `tests/testthat/fixtures`, `handoff.md`, `TODO.md`, `PROJECT_INDEX.md`, and `CLAUDE.md`. These files are in `.Rbuildignore`, so they are fine for the package, but an outside reader sees personal working notes (CLAUDE.md, handoff.md, TODO.md) at the top level. Not a reproducibility problem; consider whether they should ship in the archived release.
- **n6.** `.DS_Store` files exist under `_figures/_raw-nb` and the project root; not tracked, no effect.
- **n7.** Old package: README line 41-42 says v1.0.0 "implements the different model of the first submission." That is clear, but it does not give the tag's install command or say which figures v1.0.0 makes (CLAUDE.md: none of the current ones). One line would be enough.

## Checked and found fine

- (ran) All five scripts run to completion from a clean `_data/` and `_figures/` on a copy of HEAD, with the lockfile's package set (renv library for R 4.6.1, `--no-init-file`). Outputs: fig2-equilibria.csv, fig3-4-equilibria.csv, fig5-continuation.csv, si-table-s2.csv byte-identical to the existing ones; Fig 6 outcome counts identical (2460/1582/1524 and 4183/6826/1091). Table S2 values: reduced 0.7309 and 2.8958; full (pmax 12) 0.7297 and 2.8675.
- (ran) `renv::status()` reports "No issues found -- the project is in a consistent state."
- (ran) The scripts do not depend on Box, `.ms`, or the notebook. A grep for `Box`, `.ms`, `~/`, `/Users` in `_scripts/` finds none. `R/` and `tests/` also contain no absolute paths (the only one is in `claude-checks/`, see M5).
- (ran) Fixed seeds are present where randomness is used (`set.seed(15)` and `set.seed(777)` in `02-fig3-4.R`); I did not compare the Gillespie paths themselves (they are in an `.rds`, not in a CSV).
- (read) `.gitignore` for `_data/` and `_figures/` is sensible: all outputs are regenerable and take under 6 minutes in total, so ignoring them is acceptable. The script-to-panel mapping is clear from the file names and header comments (`01-fig2.R` is Fig 2 B-E, `02-fig3-4.R` is Figs 3-4, and so on), and each header cites the notebook section.
- (read) DESCRIPTION Imports (deSolve, Matrix, methods, parallel, stats) match what `R/` uses as far as I checked by name; Suggests covers the scripts (ggplot2, patchwork) and tests (jsonlite, testthat); all appear in `renv.lock` (ggplot2 4.0.3, patchwork 1.3.2).
- (read) Tolerances in tests are tight and sensible for deterministic linear-algebra comparisons (1e-14 for rates, 1e-13 for vacancy, 1e-9 to 1e-8 for equilibria and thresholds, 1e-6 for root-finding-limited comparisons).
- (read) Both fixture modes (chop and nochop) are tested, so the option's two states are covered against Mathematica.
